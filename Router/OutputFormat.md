# Agent Router Output Format

## Purpose

This document defines the standard output generated by Agent Router.

Every routing decision must follow this format to ensure consistency, interoperability and seamless orchestration.

---

# Routing Output Structure

```
Request Summary

↓

Intent Classification

↓

Selected Agents

↓

Execution Order

↓

Dependencies

↓

Expected Outputs

↓

Complexity Assessment

↓

Execution Plan
```

---

# 1. Request Summary

Include:

```
Request ID:

Timestamp:

Request Source:

Original User Request:

Detected Language:
```

---

# 2. Intent Classification

Identify:

- Primary Intent
- Secondary Intent (if any)
- Business Domain
- Task Category

Confidence Score:

0–100%

---

# 3. Selected Agents

For each selected agent provide:

```
Agent Name:

Reason for Selection:

Primary Responsibility:

Expected Output:
```

---

# 4. Execution Order

Specify:

1. First Agent
2. Second Agent
3. Third Agent
4. ...

Include the reason for the sequence.

---

# 5. Dependencies

Identify:

- Required inputs
- Previous outputs
- Knowledge Base references
- External systems (if applicable)

---

# 6. Expected Outputs

For each agent define:

- Deliverable
- Format
- Success Criteria

---

# 7. Complexity Assessment

Estimate:

- Complexity Level:
  - Low
  - Medium
  - High
  - Critical

- Estimated Execution Time
- Number of Agents
- Risk Level

---

# 8. Execution Plan

Summarize:

- Workflow Overview
- Assigned Agents
- Execution Sequence
- Final Recipient (usually ReportingAgent)

---

# Output Rules

Every routing decision must be:

- Clear
- Deterministic
- Minimal
- Traceable
- Easy to execute

Avoid:

- Ambiguous routing
- Duplicate agent assignments
- Missing dependencies

---

# Core Principle

The Router creates the plan.

The Orchestrator executes the plan.

The Agents perform the work.

ReportingAgent communicates the outcome.
